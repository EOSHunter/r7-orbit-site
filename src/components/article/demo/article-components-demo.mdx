## Headings

Plain `##` and `###` in Markdown already get a "link to this section" anchor. Use `Heading` when you need an explicit `id`
or a level Markdown can't give, and `Subheading` as the shortcut for level 3.

<Heading level={3} id="explicit-id">A heading with its own id</Heading>

<Subheading>A subheading under it</Subheading>

`Paragraph` is one paragraph (`lead` makes it the intro size). `Prose` wraps a run of content in the reading column when the
page isn't already inside one.

## Figures

`Figure` takes `src`, `alt`, `caption`, `align` (`left`, `right`, `center`, `full`) and `size` (`sm`, `md`, `lg`). Without a
`src` it shows the placeholder plate, as here.

<Figure alt="Placeholder for a centred picture" caption="center, md: the default alignment at a medium width." size="md" />

<Figure
  align="left"
  size="sm"
  alt="Placeholder for a picture that floats left"
  caption="left, sm: text wraps round it from 720px up."
/>

A floated figure sits beside the text that follows it, so a paragraph can run along the side of a picture. On a phone it
stacks above the paragraph instead. Keep the paragraph long enough to wrap, or the next component will clear past it.
Here is a little more text so the wrap is visible at desktop widths, which is the point of this sample.

<Figure alt="Placeholder for a picture that floats right" align="right" size="sm" caption="right, sm: the mirror image." />

The same goes for `right`. After floated pictures, headings, callouts, code and dividers all clear the float, so nothing
ever sits half beside a picture by accident.

### Pictures from a file

A `src` that starts with `/src/assets/` is an optimised picture: the build makes several widths in AVIF and WebP, so a large
file reaches a reader as a few dozen kB. This is what the editor's Image block writes for blog posts. A `src` that starts with
`/media/` is a file in `public/media/`, shown as it is. `decorative` replaces the alt text for a picture that is only decoration.

## Callouts

`Callout` takes `type` (`info`, `warn`, `tip`) and an optional `title`. The label says which kind it is, not just the colour.

<Callout type="info">An `info` callout is a plain panel for a side note.</Callout>

<Callout type="tip" title="Try this">

A `tip` is brass. It can hold **Markdown**, [links](#headings) and more than one paragraph.

Like this second one.

</Callout>

<Callout type="warn">A `warn` callout is for the thing that bites you.</Callout>

## Quotes

`Quote` is a quotation in the text. Give it `cite`, and `href` if you can link the source.

<Quote cite="A placeholder source">An agent that can break nothing is an agent you can let run.</Quote>

`Pullquote` repeats a line from the article at display size between two hairlines. Screen readers skip it because the text
is already in the body.

<Pullquote>One task, one folder, one branch.</Pullquote>

## Code

`CodeBlock` takes `code`, `lang` and an optional `title` for the bar. Colours come from the theme tokens.

<CodeBlock
  lang="bash"
  title="terminal"
  code={`git worktree add ../app.orbit/fix-header -b orbit/fix-header
npm run build`}
/>

<CodeBlock
  lang="diff"
  code={`- const rooms = 1;
+ const rooms = agents.length;`}
/>

Fenced code in plain Markdown looks the same:

```ts title="rooms.ts"
export const rooms = (agents: string[]) => agents.map((a) => `room-${a}`);
```

720px.
