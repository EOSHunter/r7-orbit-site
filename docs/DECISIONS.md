- Fonts, phase 7 (2026-10-03, for the Lighthouse budgets; owner may revisit):
  - Cormorant 500 is served by the 400 file (`font-weight: 400 500` on one `@font-face`), so section titles render at 400. One font request fewer on every page, which is what keeps LCP under 2.0 s in the mobile simulation.
  - Metric-matched fallback faces (`Cormorant Fallback`, `Inter Fallback`) sit in the font stacks, so the swap to the web fonts does not reflow headings (it caused CLS up to 0.18).
  - The Cormorant 400 italic is preloaded along with Inter and Cormorant 400 (every page has an italic-brass phrase in its headline).
  - (2026-10-06) Every face is two files split by `unicode-range` (`public/fonts/*-core-*.woff2` and `*-rest-*.woff2`), cut with fontTools from the Latin subsets that were there before, every glyph, kerning and feature kept (outlines and advance widths checked identical). "core" is U+0020-007E plus the punctuation the site prints (curly quotes, en and em dashes, ellipsis, bullet, middle dot, ×, °, ©, ®, ™, primes, ↑ ↓ →, minus); "rest" is the other Latin letters and symbols, downloaded only by a page whose text has one (an accented name, say). The two ranges do not overlap (`tests/fonts.spec.js`). The core files are a third smaller (Inter 30.8 → 18.8 KB, the Cormorant faces about 20 → 12 KB, JetBrains Mono 29.2 → 24.3 KB), which took the last LCP failures under 2.0 s without changing a glyph. To recut after replacing a font: `pyftsubset <latin file> --unicodes=<range> --flavor=woff2 --layout-features='*' --layout-scripts='*' --name-IDs='*' --notdef-outline --hinting` once per range, with the ranges from `tokens.css`. The weight-500 italic is still a file of its own (it draws the italic phrase in h3, h4 and the home rows' titles); serving it from the 400 italic, like the upright 500, would save one more request but is a visible change, so it is the author's call.
