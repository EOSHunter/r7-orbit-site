Why every agent gets its own room

Running several agents on one repo goes wrong in quiet ways. The fix turns out to be old advice about folders and branches.

When I first started giving coding tasks to agents, I let them all work in the same folder. It felt efficient. It was also how I lost an afternoon to a file that two of them had quietly rewritten in different directions.

The trouble with a shared folder

An agent that edits files is a colleague with very fast hands and no sense of what the others are doing. Put two of them in one working directory and the failure is not a crash. It is a test that passes for one and fails for the other, because the other half of the change is somewhere else.

  • They overwrite each other's edits without noticing.
  • A half-finished change from one breaks the other's test run.
  • Afterwards, nobody can say which change belonged to which task.

A worktree is a folder and a branch

Git already has the answer. A worktree is a second checkout of the same repository, in its own folder, on its own branch. I run git worktree add once per task and delete the folder when the task is merged.

terminal
git worktree add ../orbit-task-12 -b task/12-fix-login
cd ../orbit-task-12
git status

That is all of it. The agent works in ../orbit-task-12, the branch is named after the task, and my main checkout stays clean.

Nothing leaves a task's folder until I have looked at it. Sample pull quote

What approvals are for

Rooms keep agents from stepping on each other. Approvals keep them from stepping on you. An approval is the point where an agent hands a decision back and waits, and the useful question is which decisions are worth handing back.

Note. An approval is not a safety net you can stop paying attention to. It is a place where the agent admits it is not sure.

When to say no

I say no, and say why, in three cases:

  1. The command reaches outside the task's folder.
  2. The agent wants to install something I did not ask for.
  3. I cannot tell, in one read, what the command would do.

What I would change

If I started again I would write the rules down before the first task, not after the third surprise. A short list, kept in the repository, that both of us can read. Everything else I would leave to the tools, which are better at being boring than I am.
